Two runs, each with its tables, raw runs, labels and settings beside it: all four arms in
[2026-11-20T143209Z.md](2026-11-20T143209Z.md) (60 runs), and the two Claude Code arms again in
[2026-11-20T155845Z.md](2026-11-20T155845Z.md) (30 runs), because in the first the direct Claude arm

**How the findings were judged.** A person labelled every finding, 331 in the first run and 137 in
the second (the `.labels.json` files) with the seeded defect or known unseeded real issue it reports,
or as false; the metrics read only those labels. The matcher's proposals were read, grouped by the
id they named; seven were relabelled (negative quantities in `ReserveLines` belong to A4, not A2).
The fixture's real issues beyond its seeds were added as extras after reading the findings (13 in
all: a failed order leaves earlier lines reserved, expired entries are never evicted, a failed export
truncates the old report, grep reads a pattern as an option, and others). No finding of any arm was
false.

What it shows:

- **Recall does not separate the arms on this fixture**: every arm found every seeded defect in
  every run. A harder fixture (subtler defects, larger ranges, noise) is needed before claiming a
  difference in what is found.
- **The direct arms report more beyond the seeds**: two and a half to four times as many real unseeded
  issues per run (Codex 3.7 against 1.5; Claude Code 1.4 against 0.4). jackstay's prompt (severities,
  triage, the verdict form) keeps reviewers on what the change gets wrong; reading the code freely,
  they also report its neighbours' weaknesses. Worth a look before deciding the prompt's scope.
- **Speed and cost favour the wrapper**: through `jst review`, Codex took 35 s against 77 s with a
  tenth of the spread and about a third of the tokens; Claude Code took the same time and cost $0.092
  against $0.293 per range (−69 %), with about a quarter of the tokens; the first run, with the
  efforts unequal, gave the same picture ($0.086 against $0.282). The prepared patch, change
  index and view spare the reviewers their own exploration.
- **jackstay's own stages are small**: building the view took 0.2 s and nothing waited for a slot or
  the start lock (one review at a time per arm).

Limits: one machine, one small fixture, five runs per cell; two other `jst review` runs of this work
ran at the same time for part of the hour (separate stores, so no slot was shared, but the providers'
load was); Codex does not report the model it ran (the one requested is shown) nor its cost under a
subscription, so only its tokens are compared.
